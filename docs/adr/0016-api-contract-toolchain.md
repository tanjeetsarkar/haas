# ADR-0016: API contract toolchain

* Status: partially accepted. The contract and compatibility toolchain is accepted;
  the docs-portal generator and SDK generator are still open (`d-docs-portal`,
  `d-sdk-python`, `d-sdk-typescript`).
* Roadmap items: `d-api-contract`, `d-openai-compat`, `d-token-streaming`
* Related requirements/threats: FR-23, SEC-24, TUI-02

## Context

The API is consumed by:

- the CLI and TUI;
- SDKs and integrations that will be written against it;
- OpenAI-SDK users through the facade;
- webhook receivers.

Until now the only guard was an OpenAPI snapshot equality check. That check catches
drift but cannot tell an additive change from a breaking one. It also says nothing
about the SSE events or webhook bodies, which are the most integration-sensitive
surfaces.

## Decision

1. **HTTP contract.** HTTP is described by the FastAPI-generated OpenAPI 3.1 snapshot
   `docs/openapi-v1.json`. It is deterministic and regenerated by
   `python -m scripts.update_openapi_snapshot`.
2. **Event and webhook contracts.** These are JSON Schema 2020-12 documents in
   `docs/contracts/`, versioned by name (`run-events.v1`, `run-output-delta.v1`,
   `run-terminal-webhook.v1`). They are composed into AsyncAPI 3.1
   (`docs/asyncapi.yaml`). The schemas are open: `additionalProperties: true`, so
   additive changes do not break validating consumers.
3. **Producer conformance.** Schemas are enforced on the producer side, not the
   consumer side. An autouse test fixture validates every event emitted anywhere in
   the test suite and also flags *undeclared* fields, so the schema cannot drift
   behind the code.
4. **Breaking-change gate.** `oasdiff breaking --fail-on ERR` runs against the base
   commit, using a pinned container image. Intentional breaks require an entry in
   `docs/api-breaking-allowlist.txt` with a justification, plus a changelog entry.
5. **Style.** Style is enforced by Spectral (`.spectral.yaml`). Error-level rules cover
   path versioning, lowercase paths and snake_case operationIds, which become stable
   SDK method names. Missing tags/descriptions are warnings until `d-api-ergonomics`.
6. **Deprecation.** Deprecation follows RFC 9745 (`Deprecation`) and RFC 8594
   (`Sunset`), plus `Link rel="deprecation"`, with a minimum 180-day window. The window
   is enforced by `app/core/deprecation.py`.

## Consequences

- Contract checks run in a separate CI job (`api-contract`, Node 22 and Docker) and do
  not slow the Python matrix.
- Rejected alternatives:
  - Consumer-driven contract tests (Pact): there are no external consumers yet, and
    they would duplicate the producer conformance fixture.
  - Hand-written OpenAPI: it drifts from the FastAPI models.
  - Closed schemas (`additionalProperties: false`): they turn every additive field
    into a consumer break.
- Open: the docs portal (rendering OpenAPI and AsyncAPI together) and the SDK
  generator, for example openapi-python-client versus a hand-curated SDK over
  generated models. These are decided in their own roadmap items, using the snapshot
  and schemas above as inputs.
